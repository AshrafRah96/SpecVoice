# Domain Docs

Before exploring a change, read the root `GLOSSARY.md` and the relevant ADRs under `docs/adr/`. If either is absent, proceed without treating the absence as a problem.

This is a single-context repo:

- `GLOSSARY.md` contains domain vocabulary only.
- `docs/adr/` contains durable decisions, trade-offs, and consequences.

Use glossary terms consistently in issues, plans, refactors, and tests. If new work introduces a domain term, resolve it and update the glossary. If a change contradicts an ADR, surface that conflict explicitly.
